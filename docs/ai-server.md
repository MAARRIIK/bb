# Персональный AI-сервер

Это руководство описывает сервер BB для личного использования на VPS: сервер хранит диалоги и настройки, а ваши компьютеры подключаются как исполнители. Это одна учётная запись владельца, не многопользовательский сервис.

## Что подготовлено

В [`deploy/ai-server`](../deploy/ai-server/README.md) находятся Docker Compose, Dockerfile и Caddy-конфигурация. Сборка использует подготовленный пакет этого checkout, запускает только сервер без локального исполнителя, работает от непривилегированного пользователя и хранит данные в Docker volume. Порт сервера опубликован только на loopback VPS; Caddy принимает внешний HTTPS-трафик.

Файлы ещё не проверены на настоящем VPS: VPS и DNS пока отсутствуют. Также отдельно не подтверждена совместимость официального iPhone TestFlight приложения с этой авторизацией. До такой проверки используйте Safari/PWA.

## Вход владельца

`BB_OWNER_AUTH=true` включает вход владельца для веб-интерфейса, API и WebSocket. Нужны HTTPS `BB_APP_URL` и файл `server-owner-auth.json` в каталоге данных сервера. HTTP разрешён только на loopback. Без включённого флага сервер сохраняет прежнее поведение без входа владельца.

Создайте или замените пароль локальной командой, читая его из stdin:

Команды с `read` ниже рассчитаны на Bash.

```bash
read -r -s -p 'Пароль владельца: ' AI_OWNER_PASSWORD
printf '\n'
printf '%s\n' "$AI_OWNER_PASSWORD" | bb server auth set-password --data-dir /path/to/server-data --username owner --password-stdin
unset AI_OWNER_PASSWORD
```

Пароль должен содержать от 12 до 512 символов. Не передавайте его аргументом команды или через переменную окружения процесса. Смена пароля немедленно аннулирует прежние cookie владельца. Уже открытые WebSocket, включая терминалы и подписки на обновления, закрываются в течение одной секунды; входящие сообщения проверяются перед обработкой. Истечение срока сессии и повреждение файла учётных данных также закрывают эти соединения. Файл учётных данных создаётся приватным; резервные копии каталога сервера также следует считать секретными.

Откройте `https://ваш-домен`, войдите под выбранным именем и паролем. Для входа CLI на другом компьютере настройте его на тот же сервер через `BB_SERVER_URL` или обычную конфигурацию bb и выполните:

```bash
read -r -s -p 'Пароль владельца: ' AI_OWNER_PASSWORD
printf '\n'
printf '%s\n' "$AI_OWNER_PASSWORD" | bb server auth login --username owner --password-stdin
unset AI_OWNER_PASSWORD
bb server auth status
```

CLI хранит сессию в `owner-sessions` под `BB_DATA_DIR`, изолируя её по origin сервера. `bb server auth logout` завершает эту CLI-сессию. Для офлайн-инициализации каталога до запуска сервера Node SDK также экспортирует `setLocalServerOwnerPassword({ dataDir, username, password })`; не вызывайте её для действующего каталога, который нельзя менять.

В браузере выход доступен в **Settings → General → Owner session**. CLI и Node SDK отказываются передавать пароль или сохранённую сессию по открытому HTTP вне loopback.

## Подключение компьютеров

После входа владельца откройте **Settings → Machines → Add a machine** и запустите выданную команду на каждом Linux/macOS компьютере. Установщик получает пакет исполнителя от сервера и регистрирует отдельные машинные реквизиты. Пароль владельца на исполнительные компьютеры не передаётся. Отзыв машинного ключа, истечение его срока или удаление машины также закрывает уже открытые машинные WebSocket в течение одной секунды и запрещает обработку следующих сообщений. Подключённая машина — доверенный исполнитель с доступом к данным и задачам, но её реквизиты не дают права администрировать сервер, подключать другие машины, устанавливать или менять код плагинов и источники marketplace. Настройки и вызовы уже одобренных владельцем плагинов доступны исполнителю; устанавливайте только доверенные плагины. Для работы задачи соответствующий компьютер должен быть включён и подключён.

Настройте провайдеров на каждом компьютере, где они будут исполняться. Например, `bb provider` и `bb settings ai-services` управляют соответствующими локальными подключениями. Наличие диалогов на сервере само по себе не переносит локальные учётные данные провайдеров между компьютерами.

Каталог проекта, рабочие файлы и worktree остаются на выбранном исполнителе. Подключение машины не копирует содержимое её диска на VPS и не синхронизирует Git автоматически. Назначение задачи на выключенный компьютер не запускает её на VPS или другом исполнителе.

## Развёртывание и сопровождение

Подготовка домена, сборки образа, HTTPS, первого пароля, запуска и резервного копирования описана в [`deploy/ai-server/README.md`](../deploy/ai-server/README.md). Укажите свой домен в `AI_DOMAIN`; Compose передаёт его как `BB_APP_URL` и `BB_EXTERNAL_URL`. HTTPS-адрес должен совпадать с доменом и сертификатом.

`BB_APP_URL` разрешает нужный hostname и origin, но сам по себе не включает вход. Для публичного домена обязательно включите `BB_OWNER_AUTH=true` и завершите TLS на Caddy или эквивалентном HTTPS-прокси. Не публикуйте порт bb напрямую в интернет. Не восстанавливайте резервную копию поверх рабочего volume: сначала используйте отдельный Compose project и новый volume, как указано в deployment README.

Проверка на VPS, восстановление из резервной копии на целевом VPS, вход с нескольких компьютеров и iPhone Safari/PWA остаются обязательными шагами перед повседневным использованием. Не считайте TestFlight-проверку пройденной, пока она не выполнена отдельно.
