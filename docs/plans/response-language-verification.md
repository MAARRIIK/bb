## Поведение

`responseLanguage` хранится в существующем серверном хранилище настроек. Значения: `interface` по умолчанию, `en`, `ru`. Поле независимо от `interfaceLanguage`, доступно в Settings → General → AI response language, через `bb settings general responseLanguage en` и существующий SDK `system.updateGeneralSettings`. Его можно найти в русском поиске настроек. Неподдерживаемые значения отклоняются; старый PUT без поля сохраняет прежнее значение.

`interface` следует явно выбранным en/ru. При `interfaceLanguage: system` отдельный языковой блок не добавляется: модель выбирает язык по запросу. Сервер не подставляет локаль собственной ОС вместо языка удалённого телефона. Точное автоматическое следование исходному устройству ещё требует сохранения его локали вместе с запросом и остаётся отдельным пунктом roadmap.

Общий серверный построитель добавляет перед отправкой модели отдельный текстовый блок с существующей видимостью `agent-only`. Он задаёт язык объяснений, оставляет явному запросу пользователя приоритет и сохраняет исходный язык кода, путей, команд, цитат и вывода инструментов. Пользовательские блоки и сохранённая история не переписываются. Для объединённых сообщений блок добавляется в первую группу с сохранением `flatten(inputGroups) == input`. Пустой запуск и самостоятельные clear/compact не получают блок. Разбор execution options использует исходный запрос.

Используются одни и те же реализации при cold start и turn submit, включая очередь, продолжение и смену провайдера. Предпочтение читается при подготовке отправки; уже поставленное задание получает актуальную настройку при dispatch. Передавать настройку только в системных инструкциях создания сессии недостаточно: существующие адаптеры не обязаны обновлять эти инструкции на каждом turn. Отдельный блок работает через обычный ввод модели без пересоздания сессии и без новой возможности native API.

CLI, in-CLI guide, configuration и рецепт verify-bb обновлены. Новых методов SDK, wire fields и миграций нет; SDK **0.6.180**, протокол **283**. Используются прежние PromptInput и его agent-only visibility. Добавлен только ключ существующего KV-хранилища настроек, включая прежнюю совместимость сохранения для клиентов, которые его не присылают.

В одном BB thread и одном нативном Pi session file выполнены четыре запроса:

| Запрос | Настройка при отправке | Наблюдаемый ответ |
| --- | --- | --- |
| Английский запрос о переменной | ru, выбран через UI | Русское предложение с точным маркером |
| Следующий английский запрос о цикле | en, изменён через CLI | Английское предложение |
| Явное «Ответь только по-русски» | en | Русское предложение |
| Будущее задание, поставленное при ru; затем en и `bb thread queue send` | en при dispatch | Английское предложение |

Нативный session file содержит ровно четыре соответствующих блока: ru/en/en/en. Нативный процесс сохранял PID и время запуска до и после четвёртого запроса. В истории видны только эти запросы и ответы; служебный блок не появился отдельным сообщением. В базе **4 запроса и 0 toolCall rows**, Git fixture чист, очередь после четвёртого запроса пуста.
