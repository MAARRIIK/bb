# Управляющие команды в пределах сессии

Ветка: `personal/session-control-fencing`, основание `0cade27c6ab6b516a95c18ba2a02c509498403ed` — слитый [PR #7](https://github.com/MAARRIIK/bb/pull/7).

## Изменение

Остановка, переименование, архивирование, возврат из архива и отмена Plan теперь несут источник `{ providerId, providerSessionId }`. Сервер захватывает его при создании команды. Исполнитель проверяет источник до действий и повторяет проверку после асинхронных ожиданий. Для архивных команд дополнительно проверяется согласованность провайдера команды с её источником.

Переименование и возврат из архива используют существующую последовательную очередь команд диалога. Освобождение сессии в другой среде перепроверяет владельца после ожидания её незавершённых команд; при несовпадении не останавливает новую сессию. Внутренний вызов освобождения без источника сохраняет смысл операции над всем диалогом, включая удаление его хранилища. Это не команда конкретной сессии.

Ожидающий серверный цикл остановки сохраняет исходный источник на всех повторных попытках, проверяет его до следующего изменения состояния и объединяет повторные запросы только внутри одного поколения. Ответы старых команд не применяют последствия к текущему поколению. Отложенные действия результатов повторно проверяют источник и удерживают серверный барьер работы до завершения.

Исправлена и отдельная гонка runtime: ответ старого `stop` или `archive` мог стереть конфигурацию новой сессии, хотя реестр идентичностей уже сохранил её владельца. Очистка конфигурации теперь выполняется только после успешного удаления именно своего владения.

`HOST_DAEMON_PROTOCOL_VERSION` повышен с 279 до **280**. Старые сохранённые команды без `source` нормализуются в `null`: они допустимы только для прежнего null-поколения. Новые команды сервера передают явный источник даже для него. Новых миграций и пользовательских действий нет. UI, SDK и CLI продолжают использовать общий серверный путь; инструкция CLI описывает отказ устаревшим управлениям.

## Проверка

Среда: macOS arm64, Node 22.19.0, pnpm 9.15.0. Используются настоящая мигрированная SQLite и отдельные тестовые процессы агента. Рабочая база BB не использовалась.

Сфокусированный прогон до окончательных проверок: 54 проверки протокола, 89 исполнителя, 23 runtime и 52 сервера прошли.

Окончательный полный прогон выполнен одним графом Turbo, последовательно между пакетами:

| Набор | Пройдено | Пропущено |
| --- | --- | --- |
| Сервер | 4443 | 3 |
| Исполнитель | 906 | 14 |
| Runtime | 318 | 1 |
| Протокол | 97 | 0 |

Всего 5764 пройденных проверки. Пропуски не считаются пройденными; источник не менялся во время Vitest. В полном прогоне не потребовалось исправлений кода или фикстур.

Окончательные типы, lint, type-aware lint четырёх затронутых пакетов и сборки сервера/исполнителя прошли: 17 задач Turbo, без предупреждений линтера.

Отрицательные проверки подтвердили **14 сбоев** без соответствующей защиты:

- Семь типов команд принимают старый источник при отключении общей проверки. Повторная проверка владельца после ожидания другой среды тоже перестаёт защищать новую сессию — всего 8 случаев.
- Четыре варианта устаревшего ответа `release` завершают текущую фоновую задачу, если убрать фильтрацию источника результата. При включённой защите работа сохраняется, а ответ актуального поколения корректно завершает её.
- Два случая позднего ответа `stop`/`archive` стирают конфигурацию нового поколения без проверки владения. В тестах старый собственный процесс временно приостановлен `SIGSTOP`, запускается новый, затем старый продолжает работу через `SIGCONT`. После его ответа новый агент выполняет следующий ход. На Windows эти два сценария пропускаются из-за отсутствия POSIX-сигналов.

Все временные мутации восстановлены перед окончательными проверками. Тестовые процессы возобновляются и закрываются в `finally`.

```sh
pnpm exec turbo run test --concurrency=1 --env-mode=loose --filter=@bb/server --filter=@bb/host-daemon --filter=@bb/agent-runtime --filter=@bb/host-daemon-contract
pnpm exec turbo run typecheck lint lint:type-aware --filter=@bb/server --filter=@bb/host-daemon --filter=@bb/agent-runtime --filter=@bb/host-daemon-contract
pnpm exec turbo run build --filter=@bb/server --filter=@bb/host-daemon
```

Для упаковочных и системных тестов используется отдельный npm-кэш; унаследованные идентификаторы и адреса рабочего BB удалены из окружения тестов. Локальные журналы: `.tmp/toolchain/*control*fencing*` и `.tmp/toolchain/test-control-*-negative.log`. Раздельные графы тестирования не запускались параллельно.
