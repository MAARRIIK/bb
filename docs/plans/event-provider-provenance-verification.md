# Происхождение событий и сессий провайдера

Ветка: `personal/event-provider-provenance`, основание `c706ea8e8513915ce40ad06f0e49d22e44c5e60c`.

## Изменение

Раньше принадлежность сохранённой сессии определялась через текущий `threads.providerId`. Если поменять его, прежняя сессия начинала считаться сессией другого провайдера. Одинаковые идентификаторы у разных провайдеров могли конфликтовать.

Новая колонка `events.provider_id` сохраняет происхождение события. Все штатные пути записи заполняют её атомарно с записью события; оба пути копирования истории сохраняют исходное значение. Поиск владельца сессии использует происхождение события. Сессии других провайдеров не выбираются для продолжения текущего агента. Неизвестное происхождение идентификатора возвращает явное состояние `invalid`, вместо молчаливого создания новой сессии.

Сгенерированная миграция `0166_event_provider_provenance` заполняет прежние события из текущего провайдера диалога. На этой стадии смена провайдера в существующем диалоге ещё недоступна. Снимок Drizzle и журнал созданы генератором. Тестовые сценарии, которые откатывают схему, удаляют новую колонку перед повторным применением миграций.

Публичный формат событий, SDK, CLI и контракт daemon не меняются. Это внутренняя подготовка хранения, пользовательского переключателя пока нет. В установленной рабочей BB миграция не запускалась.

## Проверка

Среда: macOS arm64, Node 22.19.0, pnpm 9.15.0. Все проверки работают на отдельных настоящих SQLite, созданных штатными миграциями, без рабочей базы пользователя.

| Проверка | Результат |
| --- | --- |
| Все тесты `@bb/db`, включая планы SQL, копирование истории и миграции | 760 пройдены, 69 файлов |
| Сервер: владение сессиями, fork, редактирование, очистка контекста, события и вызовы инструментов | 168 пройдены, 8 файлов |
| Типы `@bb/db` и `@bb/server` через Turbo | Пройдены |
| Переключение текущего провайдера в SQLite при совпадающих идентификаторах сессий | Старая принадлежность сохранена; сессия другого провайдера не возобновляется |
| Копирование между разными провайдерами, обычная и переписываемая большая запись | Исходный провайдер сохранён |
| Применение новой миграции к старым строкам | Происхождение заполнено, исходный JSON не изменён |
| Идентификатор с неизвестным провайдером | Явное состояние `invalid`; очистка позволяет восстановиться |
| Проверка чувствительности теста | Без фильтра происхождения тест воспроизводит ошибочный выбор старой сессии; с исправлением проходит |

Команды:

```sh
pnpm exec turbo run typecheck --filter=@bb/db --filter=@bb/server
pnpm exec turbo run test --filter=@bb/db
pnpm exec turbo run test --filter=@bb/server -- thread-provider-identity-ownership thread-fork-history public-thread-fork thread-edit-message public-thread-context-clear-dispatch internal-events-tool-calls thread-events
```

Журналы сохранены локально в `.tmp/toolchain/*event-provenance*`. Дополнительно исправлено прежнее ожидаемое значение полных настроек в миграционном тесте: после PR #1 оно включает `interfaceLanguage: "system"`.

## Дальнейшая работа

Переключение ещё нельзя включать. Следующие изменения должны передавать происхождение от исполнителя до сервера, защищать текущее состояние от запоздавших событий старой сессии, подготавливать новую сессию с откатом при ошибке и переносить контекст с учётом доступного окна. Затем нужны единое действие UI/SDK/CLI и сквозная проверка Codex → Claude → Codex без изменения адреса диалога.

Нативные провайдеры, Linux, Safari на iPhone, VPS и восстановление его базы этим изменением не проверялись.
