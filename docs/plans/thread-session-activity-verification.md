# Обработка работы перед изменением контекста

Ветка: `personal/session-transition-guard`, основание `7d24a0e3614347275d066de5ac8a3d93f27cca30` — слитый [PR #6](https://github.com/MAARRIIK/bb/pull/6).

## Ошибка и исправление

Прежняя блокировка очистки учитывала только подготовку отправки сообщения. Обработка уже полученного события, работа инструмента и доставка его отложенного результата могли продолжаться во время очистки. Окончание HTTP-запроса не доказывает остановку инструмента: он может продолжать выполняться после отмены или вернуть промежуточный ответ, ожидая пользователя.

Общий серверный барьер теперь разделяет подготовку изменения контекста и его фиксацию. Во время остановки принимаются завершающие события агента, а фиксация допускается только при отсутствии обрабатываемой работы. Счётчики удерживаются на всём пути событий: асинхронная валидация, запись, применение последствий и запланированные после ответа действия. Запросы инструментов и подтверждений используют тот же барьер.

Реестр инструментов удерживает блокировку до завершения фактического вызова и доставки отложенного результата. Отмена HTTP сама её не освобождает. При ошибке вызова или доставки блокировка освобождается после обработки результата. Пакет событий нескольких диалогов получает блокировки целиком либо не получает ни одной.

Очистка контекста повторно проверяет существование, доступность для записи, состояние диалога и ожидающее подтверждение после остановки, внутри барьера фиксации. При занятости возвращается повторяемая ошибка 409; скрытая очистка истории не выполняется. Отправки и очередь продолжают использовать общую блокировку, её названия обобщены до изменения сессии.

Один путь `clearThreadContext` обслуживает UI, SDK `threads.clearContext`, `bb thread clear` и `/clear`. Новых публичных API или команд нет. Инструкция CLI дополнена условием занятости. Поля протокола, миграции и версия 279 не меняются; используется существующее поле ошибки `retryable`.

## Проверка

macOS arm64, Node 22.19.0, pnpm 9.15.0. Настоящая SQLite из штатных миграций, HTTP-обработчики и отдельный TCP-сервер для потокового инструмента. Рабочая база BB не затронута.

- Сфокусированный набор: 76 проверок в 6 файлах прошли.
- Полный серверный прогон: 4360 пройдено, 3 пропущено; 77 ошибок среды в 7 файлах. Повтор этих файлов с системными процессами, наблюдателями и доступным npm-кэшем, вместе с двумя новыми случаями состояния диалога: 193 пройдено в 8 файлах. В совокупности прошли 4439 разных проверок сервера; штатные пропуски не объявляются пройденными.
- Окончательный сфокусированный повтор после всех отрицательных проверок: 92 пройдено в 7 файлах.
- Окончательные сборка, типы, lint и type-aware lint сервера: 9 задач Turbo прошли.
- Отрицательная проверка реестра: без удержания блокировки падают три случая — потоковый ответ, отмена HTTP и отложенная доставка.
- Отрицательная проверка событий: без удержания блокировки очистка возвращает 200 во время незавершённой валидации; новая проверка требует 409 и сохранённую историю.
- Отрицательная проверка состояния: без повторной проверки после остановки падают оба случая архивирования и удаления диалога; с ней они сохраняют контекст и возвращают 409.
- Проверка атомарности: отказ пакету из-за одного диалога не оставляет другой занятым; ошибка фиксации освобождает исключительную блокировку.

```sh
pnpm exec turbo run test --filter=@bb/server -- thread-session-guard.test.ts plugin-tool-calls.test.ts internal-extension-payloads.test.ts internal-events-tool-calls.test.ts public-thread-context-clear-dispatch.test.ts internal-interactive-requests.test.ts
pnpm exec turbo run test --filter=@bb/server
pnpm exec turbo run typecheck lint lint:type-aware --filter=@bb/server
pnpm exec turbo run build --filter=@bb/server
```

Для повторения упаковочных тестов использован `--env-mode=loose` с предварительно удалёнными из окружения тестов унаследованными `BB_CLI`, `BB_CLI_REEXEC`, `BB_SERVER_URL`, `BB_THREAD_ID`, `BB_ENVIRONMENT_ID`, `BB_THREAD_STORAGE`, `BB_PROJECT_ID` и `BB_HOST_DAEMON_PORT`. Это сохраняет отдельный `npm_config_cache` и не подключает проверки к рабочему BB. Системный npm-кэш не исправлялся сменой владельца. Локальные журналы: `.tmp/toolchain/*session-guard*`. Предупреждение очистки временных процессов из-за запрета sandbox на `ps` отделяется от результатов тестов.

## Ограничения

Это защита серверной операции, а не включённое переключение провайдеров. Перед его включением ещё нужны защита команд остановки и архивирования, проверка активной и фоновой работы на исполнителе, подготовка целевой сессии с восстановлением при ошибке и пакет контекста. Счётчики действуют в процессе сервера; они не заменяют сохранённое намерение перехода и сверку с исполнителем после перезапуска. Инструмент, который игнорирует отмену и продолжает работать, блокирует фиксацию до своего фактического завершения. Сквозное переключение настоящих Codex/Claude, Linux и iPhone этим этапом не подтверждено.
