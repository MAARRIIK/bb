# Переключение модели в существующем диалоге

Основание — `733a505676ac16cfd0f960e284627f86f666238f`, слитый [PR #11](https://github.com/MAARRIIK/bb/pull/11). Серверный журнал теперь имеет пользовательский путь запуска: действие в заголовке диалога, `threads.experimental_providerSwitch` в SDK и `bb thread provider` в CLI используют один контроллер.

Перед переключением пользователь выбирает подключение, модель и разрешения, затем получает точный текст передачи. Можно использовать последние видимые сообщения или собственную сводку. Сервер исключает скрытый ввод, рассуждения, инструменты, дочерние сообщения и содержимое вложений; распознаваемые ключи и пароли скрываются. Это частичный контекст, а не обещание перенести всю историю. Ранние сообщения остаются доступны через `bb thread log --self`.

Чтение истории ограничено последними 64 подходящими событиями; слишком большие строки исключаются в SQL до загрузки содержимого. Пакет ограничивается консервативной оценкой по числу байтов UTF-8, без обрезания внутри символа. Для известного окна под передачу используется не более четверти его размера. Неизвестное окно, размер из каталога и пользовательская декларация различаются; фактическое окно исполнителя автоматически проверенным не считается.

Предпросмотр связан с исходным поколением, рабочей средой, параметрами и границей истории. Изменённый или устаревший пакет нельзя применить. Повтор одного UUID использует сохранённый результат; CLI сохраняет файл просмотра с правами `0600` и отказывается его перезаписывать. После разрыва соединения UI читает сохранённую операцию и предлагает сверку с исполнителем.

Pi передаёт необязательное `AvailableModel.experimental_contextWindowTokens` только для положительного целого значения из своего каталога. Версия протокола исполнителя повышена с **282 до 283**. SDK и свойство каталога описаны в Plugin Guide и `docs/api_to_audit.md`; команды и флаги — в CLI Guide и индексе навыка.

## Автоматическая проверка

Серверные сценарии используют настоящее приложение, HTTP и SDK, мигрированную SQLite и подтверждения на границе RPC исполнителя. Одна таблица контрактов запускается для трёх поверхностей. Проверены точный состав пакета, исключение скрытых данных и секретов, сводка, ограничения окна, Unicode, пропуск больших событий, очистка истории, потолок прав машины, идемпотентность и восстановление. До подтверждения не отправляется пользовательский ход целевой модели.

Полные проверки: сервер **4482 passed / 3 skipped**, база **773 passed**, SDK **135 passed**, domain **368 passed**, контракт исполнителя **97 passed**, Pi **371 passed / 6 skipped**, Plugin Guide **76 passed**, CLI **1421 passed / 1 skipped**. Дополнительно интерфейс переключения и существующий заголовок: **40 passed**. Итого **7763 passed / 10 skipped**; полный набор интерфейса не запускался.

Полный серверный прогон прошёл с первого раза. Первый полный CLI-прогон выявил неподходящие заглушки UUID/файла в общей проверке ошибок сервера и порядок импорта тестового транспорта. После исправления фикстур весь CLI прошёл. В проверке JSON сравнивается структура, а не порядок ключей.

Браузерная проверка воспроизвела ошибку строгого React Compiler: обработчики внутри компонента использовали неподдерживаемые конструкции `try/finally` и условные значения внутри `try`. Обработчики исправлены без отключения компилятора. Окончательная сборка, типы, lint и type-aware lint прошли: **34 задачи Turbo**. Тесты интерфейса повторены после исправления. Источник и тесты не менялись во время Vitest.

```sh

```

Переменные рабочего BB исключены из тестовых процессов; используется Node 22.19.0. Графы Turbo с общими генерируемыми модулями запускались последовательно. Журналы: `.tmp/toolchain/test-provider-switch-*.log`, `.tmp/toolchain/build-provider-switch-final.log`.

## Настоящие модели и браузер

Проверка выполнена на macOS в отдельной рабочей копии с новой помеченной базой, собственными портами и исходным CLI. Маркер владения, рабочие каталоги процессов и подключение исполнителя проверены до действий. Для Pi создан отдельный каталог конфигурации и обёртка с закреплённым Node; пользовательские настройки Pi не менялись. Отдельная QA-модель Ollama использовала веса установленной `qwen2.5:7b` с `num_ctx 32768`; исходная модель не изменялась.

Пройден сквозной сценарий:

1. Codex получил контрольную фразу и ответил. В браузере выбран Pi/Qwen, показаны два сообщения и размер окна 32768; полный доступ выбран явно.
2. Подтверждение завершило переход, сохранив ID диалога и рабочую папку. Следующий запрос не содержал самой фразы. Qwen вызвал инструмент записи и создал `continuity.txt` с правильным содержимым; получен настоящий завершённый ответ. `/api/ps` Ollama подтвердил фактическое окно **32768**.
3. После перезагрузки страницы на ширине **390 × 844** сохранены история и модель. Мобильная панель использует общий постоянный drawer, не добавляет `inert`/`aria-hidden` корню приложения и не создаёт горизонтальную прокрутку. Предпросмотр сохранился при закрытии и повторном открытии.
4. Обратный предпросмотр включил сообщения Qwen. После подтверждения Codex прочитал созданный файл командой `cat continuity.txt` и вернул правильную фразу. ID диалога и рабочая папка сохранились.
5. Тестовые сервер и исполнитель остановлены и запущены с той же собственной базой. Сохранились провайдер, завершённая операция и история. Следующий настоящий ответ Codex после перезапуска снова содержал правильную фразу.
6. Исходным CLI проверены `provider preview`, приватный файл просмотра, `status` и идемпотентный `recover` завершённой операции.

Снимки интерфейса просмотрены. Тестовые службы и отдельный браузер остановлены, свободны все пять портов. Помеченная QA-база, синтетическая рабочая папка и отдельная QA-модель удалены; исходная Qwen сохранена. Локальные свидетельства находятся в `.tmp/verify-provider-switch-20261123/`; они не публикуются вместе с исходниками.

## Оставшиеся границы

Это отдельное действие в заголовке. Обычный выбор другого провайдера в редакторе пока использует прежний handoff в новый диалог. Автоматическая сводка целей, повторное использование прежних сессий и задания очереди с разными провайдерами остаются следующими этапами.

Настоящий ответ Claude, облачные API с пользовательскими ключами, Linux, Safari на iPhone, установка PWA и VPS в этом изменении не проверены. Chromium на мобильной ширине не заменяет проверку Safari. Свежая установка потребовала штатной генерации служебного worker через Turbo перед `pnpm dev`. В браузере наблюдалось существующее предупреждение о нескольких экземплярах Jotai.

Проверка карты навыка остановилась на существующей непокрытой семье CLI `diagnostics`. Базовая линия карты не перезаписана; полного покрытия карты не заявляется.
