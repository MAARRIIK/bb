# Источник события от исполнителя до сервера

Ветка: `personal/daemon-event-origin`, основание `daf9d33ec322cb63ff79547792d7e65bd997476f` — слитый [PR #3](https://github.com/MAARRIIK/bb/pull/3).

## Изменение

Исполнитель передаёт `providerId` отдельно от данных события. Источник берётся из процесса агента при получении события, сохраняется в очереди доставки и в группах пакета. События одного диалога от разных провайдеров не объединяются в одну группу. Watchdog и сообщения о падении процесса сохраняют источник исходной операции.

Сервер проверяет машину, диалог и провайдера. Событие другого провайдера отклоняется с `provider_mismatch`. Неизвестный источник отклоняется с `missing_provider`; `null` разрешён только для сообщения исполнителя о подготовке рабочей папки (`system/thread-provisioning`). Дополнительно проверка повторяется после асинхронной валидации расширений, непосредственно перед синхронной записью. Ответ сохраняет исходные индексы принятых и отклонённых событий.

`events.provider_id` заполняется переданным источником, а не текущим провайдером из строки диалога. Ранее сохранённая история остаётся доступной. При назначении диалога другому процессу реестр исполнителя удаляет прежнюю привязку и идентификатор его сессии, чтобы позднее событие не восстанавливало прежнюю принадлежность. Запоздалая очистка прежнего процесса сохраняет новую привязку.

Контракт server/daemon изменён: `HOST_DAEMON_PROTOCOL_VERSION` повышен с 277 до 278. Старый исполнитель должен обновиться; незаметный приём пакетов без происхождения не поддерживается. Провайдерный bridge-протокол и Plugin SDK не меняются: источник добавляет сам runtime. Дополнительной миграции базы после PR #3 не требуется. Пользовательских UI/SDK/CLI действий этот внутренний этап не добавляет.

## Проверка

Среда: macOS arm64, Node 22.19.0, pnpm 9.15.0, отдельные SQLite и тестовые процессы. Рабочие диалоги и база установленного BB не используются.

Проверки охватывают смешанные источники в пакете, буферизацию до переподключения, поздние и неизвестные идентификаторы, переход между процессами одного или разных провайдеров, смену провайдера во время асинхронной валидации и сторонний echo-провайдер через настоящий runtime и сервер.

Основные команды:

```sh
pnpm exec turbo run typecheck lint:type-aware --filter=@bb/db --filter=@bb/server --filter=@bb/host-daemon --filter=@bb/agent-runtime --filter=@bb/host-daemon-contract
pnpm exec turbo run test --filter=@bb/db --filter=@bb/host-daemon --filter=@bb/host-daemon-contract --filter=@bb/agent-runtime
pnpm exec turbo run test --filter=@bb/server
```

| Проверка | Результат |
| --- | --- |
| Все тесты базы | 760 пройдены |
| Все тесты runtime после окончательной правки | 315 пройдены, 1 пропущен |
| Весь контракт исполнителя | 97 пройдены |
| Полный прогон исполнителя и исправленные ожидания | 894 пройдены в полном прогоне; оставшиеся 3 случая исправлены и прошли в целевом прогоне из 95 тестов; 14 пропущены |
| Полный серверный прогон и исправленные случаи | 4430 пройдены; 2 сбоя исправлены и прошли в целевом прогоне из 26 тестов; 3 случая пропущены из-за отсутствующих корпусов истории |
| Типы и type-aware lint пяти затронутых пакетов | Пройдены; окончательные правки runtime/server перепроверены |
| Сборка сервера и исполнителя через Turbo | Пройдена |
| Поздняя очистка прежнего процесса | Новый тест воспроизвёл удаление новой сессии до исправления и прошёл после |

В полном серверном прогоне выявлен прежний непереносимый тест даты Git: `Z` и `+00:00` сравнивались как разные строки. Ожидание теперь сравнивает один и тот же момент времени. Второй сбой исправлен явной меткой `acp-opencode` в примере нестандартного провайдера. Повторный полный прогон не выдаётся за выполненный: исправленные файлы и сквозной echo-сценарий проверены отдельно. Журналы находятся локально в `.tmp/toolchain/*daemon-origin*`.

## Оставшаяся работа

Само переключение пока не включено. Метки провайдера недостаточно для различения нескольких сессий одного провайдера, в том числе разных API-моделей внутри Pi. Нужны границы сессий, подготовка с откатом, блокировка перехода относительно отправки и применения событий, перенос контекста и единое действие UI/SDK/CLI.

Linux, iPhone Safari, реальные API-подключения и VPS этим этапом не подтверждаются. VPS у пользователя пока нет; подготовку воспроизводимого развёртывания можно сделать локально, проверка на сервере остаётся отдельным условием приёмки.
