# Остаток квот и происхождение показаний

Дата: 24 ноября 2026. Основа: PR #19, `ac5ac470c60cc2da522d4a04097953f4ef842574`. Проверенные исходники: `46992e6e696b030d23b280ab98b3ea3cd95f6d1d`; после живой проверки добавлена только документация.

## Изменение

Источники уже публиковали observedAt, ID окна и семейство моделей, но агрегатор Provider usage отбрасывал их. Теперь карточка и настройки сохраняют и показывают источник, время последнего измерения, остаток квоты и область её действия. Общая квота аккаунта не выглядит отдельным лимитом каждой модели. ID окна используется как ключ вместо потенциально одинакового текста подписи.

Карточка показывает оставшийся процент рядом с полосой расхода. Раскрытие добавляет расход, точное время сброса с часовым поясом устройства и область квоты. Настройки показывают эти подробности сразу. Часовые, месячные и другие пользовательские окна отображаются только с подписью источника. Новые окна и оценки числа запросов не выдумываются. При расходе выше 100% остаток равен нулю; превышение остаётся видно в подробностях.

Показания старше пяти минут, данные после ошибки обновления или отключения исполнителя отмечаются устаревшими. Пометка возраста обновляется раз в минуту. Успешное обновление показывает новое время источника. Время загрузки кеша не заменяет время измерения; отсутствующая или недопустимая дата означает неизвестное время. Ошибка не стирает предыдущие показания.

CLI и SDK используют существующий RPC `bb--provider-usage/getUsage`. Ответ сохраняет source, nullable observedAt и id/model окна. README содержит пример `bb plugin rpc call ... --input-file ... --json`, просмотр схемы и путь SDK. Контракты источников, SDK exports, серверная БД и host-daemon wire не менялись; протокол остаётся **283**. Подготовка очереди по подтверждённым квотам — отдельный этап.

Промежуточные прогоны выявили прежние точные UI-ожидания расхода и текста раскрытой строки; они обновлены под новый вид. ## Настоящее приложение

Отдельный checkout проверенного коммита, новая помеченная база, пять собственных портов и отдельный браузерный профиль. Первый запуск свежего checkout обнаружил отсутствующий generated profile-worker; штатная сборка scripts/CLI через Turbo подготовила его, затем server/daemon запустились и исполнитель подключился. Рабочая IDE и её база не использовались.

1. CLI прочитал схему и вызвал настоящий агрегирующий RPC. Codex сообщил одно недельное окно; значения расхода и остатка, source и observedAt сохранены локально для сверки. Другие периоды не заявлены как доступные этому аккаунту.
2. Настоящим нажатием открыта карточка, затем раскрыта строка квоты. Остаток, расход, источник, измерение, точная дата сброса и общая область аккаунта совпадают с ответом сервиса. Проверено отсутствие горизонтального переполнения. Первый screenshot был снят во время анимации высоты; окончательный снимок сделан после её завершения и просмотрен.
3. Через настройки открыта полноразмерная панель. Просмотрены desktop 1440×1000 и Chromium 390×844. На узком экране боковая панель закрыта, подробности квоты видны, ширина страницы равна 390, корень не получил inert/aria-hidden.
4. В изолированном браузере перехвачен и прерван только запрос обновления getUsage. Настройки сохранили прежний остаток и прежнее время измерения, показали предупреждение и Last measurement (stale). Перехват снят в finally. Эмуляция offline перед этим не воспроизвела ошибку loopback-запроса и не считается доказательством сбоя.
5. Настоящая кнопка обновления повторно вызвала сервис. Пришло новое observedAt, отметка устаревания снялась, данные остались видны. Последующий CLI read вернул точно то же время измерения, что элемент time в UI. Итоговая сверка также подтвердила источник, остаток и usable root; активных агентских заданий нет.

Свидетельства: `.tmp/verify-usage-details-20261124/`, включая `usage-real.json`, `usage-real-final.json`, `rpc-schema.json`, `final-summary.json`, `usage-card-desktop-settled.jpg`, `usage-settings-desktop.jpg`, `usage-settings-mobile-visible.jpg`, `usage-failed-refresh-mobile.jpg`, `usage-recovered-mobile.jpg` и соответствующие snapshots. Приватные данные аккаунта и сырые screenshots не включены в Git.

Браузер остановлен. Принадлежность launcher и его процессов проверена по PID, команде, cwd и маркеру базы. После штатной остановки все пять портов свободны, процессов этой сборки не осталось; удалена только её помеченная база. Checkout и доказательства сохранены.

## Открытые пункты

Настоящие почасовые/месячные квоты и другие аккаунты не проверены. iPhone Safari, Linux, Android и VPS не проверены; Chromium на macOS их не заменяет. Существующая ошибка inventory verify-bb `Unmapped CLI family: diagnostics` остаётся открытой, baseline не переписан.
