# Заметный вход в очередь с разными моделями

Проверка 24 ноября 2026 года после PR #31. Пользователь не нашёл назначение
модели каждому запросу и отметил, что текущую модель нельзя переключать до
завершения предыдущего ответа.

Назначение уже существовало в PR #17 и в замороженной рабочей сборке после
PR #29. Но маленькая ghost-кнопка над редактором была недоступна для пустого
черновика и не объясняла последовательность действий. На экране создания
диалога без готовой рабочей папки это действие отсутствует.

## Изменение

В готовом диалоге над полем ввода показан подписанный блок «Очередь с разными
моделями». Подсказка объясняет: ввести запрос ниже, выбрать модель, добавить в
очередь и повторить. Кнопка «В очередь с моделью» теперь outline вместо ghost.
Английский и русский тексты следуют общему языку интерфейса.

Нового механизма очереди, API, настройки или хранения нет. Используются те же
`QueueDraftWithModel`, форма назначения и SDK `threads.queuedMessages.create`.
CLI остаётся `bb thread queue create --provider ... --model ...`.
Пустой черновик по-прежнему нельзя отправить. Форма редактирования задания не
меняет свой стиль. Главный picker текущей модели остаётся отдельным действием.

Назначение будущей модели не переключает работающего агента. Запуск задания и
автопереход возможны после завершения текущего хода и выполнения условий очереди.
Если следующий запрос должен ждать успешного результата конкретного задания,
нужно выбрать его в «Дождаться успешного завершения заданий». Без разрешённого
автоперехода задача другого провайдера ждёт ручного выбора этого провайдера.
