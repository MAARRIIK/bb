# Актуальные сведения в пределах поколения провайдера

Основание: `3f5426cde1fa9c22aaff1d43d5cb5bc1b013604a`, слитый [PR #9](https://github.com/MAARRIIK/bb/pull/9).

При будущей смене поколения текущие настройки, цель, список команд, расход контекста, план и сообщение о резервной модели могли читаться из старой сессии. Прогретый кэш сохранял последнюю строку прежнего владельца. Последние параметры запуска также выбирались из всей истории.

Чтение актуальных сведений теперь проверяет провайдера и поколение в SQL. Legacy-события с неизвестным провайдером допускаются только при совпадении поколения. Проверка применяется и при повторном чтении строк из кэша; если сохранённая строка больше не принадлежит текущей сессии, выполняется имеющийся повторный поиск. Параметры запуска используют тот же запрос последних сообщений с явной областью `current-session`; запрос к истории по умолчанию сохраняет область всего диалога.

История не переписывается и не скрывается. Очистка старых снимков контекста продолжает искать границу во всей истории, отдельно от показаний текущей сессии. Миграций, новых wire-полей, настроек и пользовательских действий нет. UI, SDK и CLI получают исправленное состояние через существующий серверный путь. Переключение провайдеров ещё не включено.

## Проверка

Два новых случая на настоящей мигрированной SQLite проверяют смену провайдера и смену поколения того же провайдера. Они прогревают кэш, меняют владельца, добавляют запоздалые события прежнего поколения и события постороннего провайдера с совпадающим поколением, затем возвращаются к исходному владельцу. Проверяется, что текущие сведения изолированы, а вся история остаётся доступной. Фикстура использует штатный `appendDaemonEventsInTransaction`, сохраняющий источник события.

Эти проверки падают на прежнем коде с выдачей старого состояния. Журнал отрицательного прогона: `.tmp/toolchain/test-current-provider-state-negative.log`; исходник восстановлен перед дальнейшими проверками.

Окончательно прошли:

- Все **765** проверок пакета базы данных, включая планы запросов, кэш, сохранение истории и очистку событий.
- **166** серверных проверок в восьми файлах: состояние диалога, настройки сессии, последние параметры, модель и права, отправка сообщений.
- Типы, lint и type-aware lint базы/сервера: 9 задач Turbo; `git diff --check`.
