# Подготовка входа по подпискам через ACP

Дата: 24 ноября 2026. Рабочая ветка: `feat/subscription-agent-sign-in`, основа
персонального main после PR32 (`6bbb107`). Рабочая IDE пользователя на PR29
не менялась и не перезапускалась.

## Изменение

Страница Subscriptions и кнопка в настройках ACP добавляют профили официальных
Antigravity, Kimi Code и облачного Qwen Code. Используются существующие ACP,
customAgents и терминалы BB. Нового OAuth-клиента, исполнителя и хранения токенов
нет. Команды Kimi/Qwen закреплены на опубликованных версиях 2.7.3/0.28.4;
Node engines npm проверены (Kimi >=22.19.0, Qwen >=22.0.0). Google требует
установленного `agy`.

UI, `bb acp subscriptions list|add|login` и SDK `plugins.callRpc` используют
одни операции. Профили не заменяют существующие настройки. Изменённые command,
args, env или cwd требуют собственного входа. Машину нужно выбрать явно.
Добавление профиля, создание терминала и успешный OAuth — разные состояния.

## Проверки

`pnpm exec turbo run test typecheck lint --filter=bb-plugin-provider-acp`:
**107 тестов в 10 файлах**, **10 задач успешно**. Новые проверки проходят через
реальный plugin entry и стандартный SDK harness с SQLite, без mock базы:
параллельное сохранение профилей, reload, CLI/RPC, native команды трёх агентов,
неподключённая машина, изменённое окружение/команда/cwd, повторная проверка после
ожидания машины, повторное и одновременное открытие терминала. UI проверяет
RU/EN, явный выбор машины, повторные клики, отказ RPC и навигации с сохранением
receipt, переход из настроек на страницу подключений.

В существующем Vitest include отсутствовал src/**/*.test.tsx; добавлен этот
паттерн, чтобы новый UI suite действительно выполнялся. Сохранена существующая
автономная конфигурация forkable-плагина: импорт корневого vitest.shared ломает
его отдельную копию и отклоняется обязательным forkable-plugin-imports lint.

Живая QA: отдельный checkout `.tmp/confirmed-limits-qa-20261124`, свежий store
с owner-маркером, server21716/daemon29716, Node22.19.0. Проверены ownership PID/cwd,
health и подключённая машина. Оптимизированный bundle собран штатным launcher.
Доказательства сохранены локально в `.tmp/verify-subscriptions-20261124`.

## Границы

Пользовательские подписки, настоящий Google/Kimi/Qwen OAuth, модельный запрос,
расходование квоты и перенос между машинами не проверены. Ни одна успешная
операция настройки не представлена как доказательство доступа к подписке.
GLM/ZCode требует отдельной проверки версий официального CLI и community ACP.

Read-only inventory helper заблокирован существующим `Unmapped CLI family:
diagnostics`: diagnostics command уже присутствует в исходном main, helper и
его ownership этим изменением не затронуты. Новый рецепт ACP обновлён вручную;
общая карта не объявляется полностью прошедшей проверку.

Новых SDK exports или server/daemon wire fields нет; используется существующий
terminal API, поэтому protocol284 не меняется. CLI и конфигурация описаны в
ACP skill и docs/configuration.md. Удалённые GitHub checks оцениваются отдельно
от локальных проверок; отсутствие workflow не означает зелёный CI.
