# Поколение сессии от процесса до сервера

Ветка: `personal/provider-session-transport`, основание `6d1aa95718bf78947edadf43f3b95b67ea8f2de7` — слитый [PR #5](https://github.com/MAARRIIK/bb/pull/5).

## Изменение

Поколение в базе само по себе не отличает запоздавшую работу агента. Если определять его при вставке по текущему диалогу, старый ответ получит новую метку. Теперь источник `{ providerId, providerSessionId }` закреплён за отдельным процессом агента и передаётся вместе с событиями, вызовами инструментов и запросами подтверждения.

Очередь событий копирует источник при постановке в очередь; повторная отправка его сохраняет. Группировка не объединяет соседние события разных поколений одного провайдера. Сервер проверяет текущего владельца и поколение до записи, повторяет проверку после асинхронной валидации событий и сохраняет именно доставленный источник. Старые инструменты и подтверждения отклоняются до побочных действий.

Разные явные поколения используют разные ключи процессов. Возобновление и обычный запуск уже размещённого диалога требуют совпадения провайдера и поколения. Повторяющийся запрос подтверждения из другого поколения не получает обещание ответа от старого запроса. События завершения процесса и отложенные предупреждения тоже сохраняют исходное поколение.

`HOST_DAEMON_PROTOCOL_VERSION` повышен с 278 до **279**. События используют обязательный `source`; `null` разрешён сервером только для собственного события подготовки среды. Отсутствующий источник запросов и отсутствующее поколение команд нормализуются в `null` на границе для прежних диалогов. Запрос без источника не допускается в диалог с явным поколением. Серверные команды запуска и возобновления передают поколение из базы, захваченное до асинхронной подготовки.

Новой миграции нет: используются колонки миграции 0167. Нового пользовательского действия UI/SDK/CLI пока нет. Переключение не включено.

## Проверка

macOS arm64, Node 22.19.0, pnpm 9.15.0; настоящая SQLite из штатных миграций, отдельные скриптовые процессы агента. Рабочие диалоги и база BB не использовались.

| Проверка | Результат |
| --- | --- |
| База, полный прогон и повтор исправленной фикстуры | 762 случая прошли в полном прогоне; единственная ошибка фикстуры исправлена и весь её файл из 45 случаев прошёл |
| Agent runtime, окончательный полный прогон | 316 пройдено, 1 пропущен; реальный мост подтвердил смену процессов и происхождение событий для двух поколений одного диалога |
| Host daemon, окончательный полный прогон | 900 пройдено, 14 пропущено |
| Протокол, полный прогон | 97 пройдено; уточнённый случай группировки разных поколений дополнительно проверен отдельно |
| Сервер, полный прогон | 4433 пройдено, 3 пропущено; 2 ошибки ожидаемых данных фикстуры исправлены, весь файл из 14 случаев прошёл повторно |
| Сквозной серверный canary | 2 пройдено: настоящий мост, HTTP-доставка событий, запись в SQLite и поток ответа |
| Отрицательная проверка защит | При временном удалении сравнения поколения падают оба случая команд; без серверной проверки падает случай инструмента с побочным действием. После восстановления весь соответствующий набор проходит |
| Типы и type-aware lint сервера, исполнителя, runtime, базы и протокола | Пройдены, 15 задач Turbo |
| Сборки сервера и исполнителя | Пройдены |

Добавлены проверки старых событий, отсутствующего и неверного источника инструмента без вызова обработчика, подтверждений без создания записи, отказа старым `thread.start`/`turn.submit`, неизменности очереди и коллизии подтверждений между поколениями.

Один первоначальный параллельный запуск двух отдельных графов Turbo пересоздал общий каталог тестовых мостов во время тестирования. Три проверки не загрузили файл моста. Последовательный полный повтор runtime прошёл; этот сбой не скрыт исправлением продуктового кода. Прогоны следует запускать одним графом Turbo либо последовательно. Ограничение sandbox на `ps` выдало предупреждение очистки после успешного прогона runtime; собственные временные каталоги проверяются отдельно.

```sh
pnpm exec turbo run test --filter=@bb/db
pnpm exec turbo run test --filter=@bb/db -- data/threads.test.ts
pnpm exec turbo run test --filter=@bb/agent-runtime --filter=@bb/host-daemon --filter=@bb/host-daemon-contract
pnpm exec turbo run test --filter=@bb/agent-runtime
pnpm exec turbo run test --filter=@bb/server
pnpm exec turbo run test --filter=@bb/server -- internal-extension-payloads.test.ts
pnpm exec turbo run test --filter=@bb/server -- echo-provider-canary.test.ts
pnpm exec turbo run typecheck lint:type-aware --filter=@bb/server --filter=@bb/host-daemon --filter=@bb/agent-runtime --filter=@bb/db --filter=@bb/host-daemon-contract
pnpm exec turbo run build --filter=@bb/server --filter=@bb/host-daemon
```

Локальные журналы: `.tmp/toolchain/*session-transport*`. Пропуски штатных наборов не объявляются пройденными.

## Следующий этап

До включения смены модели нужны исключительная операция перехода, ожидание уже начатых инструментов и фоновой работы, защита остальных команд жизненного цикла, подготовка новой сессии с восстановлением при сбое и ограниченный реальным окном пакет контекста. Текущая проверка источника не отменяет инструмент, который уже выполнялся до неё. Проверки настоящих Codex/Claude, Linux и Safari на iPhone ещё не выполнены. VPS пока отсутствует; можно подготовить развёртывание и восстановление локально, но нельзя считать их проверенными на VPS.
