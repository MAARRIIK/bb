# Проверка персонального AI-сервера

Дата: 25 ноября 2026. Подготовка на основе `MAARRIIK/bb main` после PR #41, версия AI `0.50.3`. Настоящего VPS и DNS пока нет; рабочая пользовательская AI не переводилась на другой сервер.

## Реализовано

Опциональный `BB_OWNER_AUTH` закрывает веб-интерфейс, API и WebSocket входом одного владельца. Приватный файл хранит соль, scrypt-хеш и ключ подписи семидневных cookie. Пароль читается из stdin, HTTP вне loopback не допускается для передачи пароля или owner cookie через Node SDK. Смена пароля отзывает старые cookie; действующие owner WebSocket закрываются в течение секунды, а сообщения проверяются до обработки.

Подключённые компьютеры используют собственные машинные ключи через локальный daemon proxy. Они сохраняют доступ к рабочим данным, но не получают управление машинами, переносом сервера, установкой серверных плагинов и каталогами. Для новой owner-конфигурации выбирается прямой доступ к своему адресу; существующий явный выбор сохраняется. Протокол исполнителя повышен до `285`.

Общий путь входа доступен через HTML-форму, `experimental_ownerAuth` в SDK и `bb server auth set-password|login|status|logout`. В общих настройках есть выход из браузерного сеанса. Dockerfile запускает сервер без локального исполнителя от обычного пользователя; Compose хранит данные в volume и предоставляет Caddy для HTTPS.

## Локальные проверки

Проверки выполнялись в отдельном detached checkout `/private/tmp/ai-server-source-20261125`, с отдельными каталогами сервера, исполнителя, CLI и браузерными профилями. Исходники и данные рабочей AI не использовались как QA-профиль.

- Turbo: 21 задача typecheck/lint прошла для server, app, CLI, SDK, host-daemon, bb-app и Plugin Guide.
- Целевые тесты: 60 passed в восьми файлах. Проверены криптография и права файла, ограничения входа и тела запроса, поддельные gate-заголовки, действующий и отозванный machine key, административные запреты, настоящие WebSocket, HTTP/WS cookie транспорт и UI ошибки выхода.
- Полные связанные наборы: config 104 passed / 1 skipped, SDK 140 passed, bb-app 231 passed. CLI: 1438 passed / 1 skipped по полному прогону и повторной матрице из 476 команд после исправления генерации аргументов обязательных boolean-флагов. Локальная `set-password` явно отмечена как команда без сервера; `login` проходит общий контроль серверных ошибок.
- Plugin Guide: 76 passed, включая проверку существования публичных символов SDK.
- Контроль регрессии: отдельно отключались owner и machine WS guard в QA-копии. Оба теста падали с открытыми соединениями `[1, 1]` вместо `[3, 3]`. Исходник восстановлен побайтно; все семь серверных auth-тестов снова прошли.
- Максимальный допустимый пароль с кириллицей воспроизводимо не проходил URL-encoded HTML-форму (`401` вместо `303`). Лимит тела увеличен до 8192 байт с сохранением ограничений полей; регрессия проходит.
- `server:package`: 71 задача сборки прошла; создан архив, SHA256 и сведения о сборке. Это development-архив из изменённого checkout.
- `smoke:server`: 72 задачи прошли. Архив установлен в новый каталог; настоящий сервер и исполнитель запущены на собственных портах. Проверены запреты анонимного API/WS, вход/выход CLI и приватный файл cookie, два независимых SDK-клиента, общий отложенный диалог, прямой доступ по умолчанию, перезапуск и восстановление офлайн-копии в другой каталог. Внешний провайдер модели не вызывался: запрос оставался отложенным.

Проверка настоящим Chromium обнаружила ошибку формы: `Referrer-Policy: no-referrer` приводила к `Origin: null` при POST. Политика изменена на `same-origin`; повторный ввод через форму дал POST `303` с правильным Origin и открыл AI. Проверены отдельные desktop и мобильный браузерный профиль 390×844: вход, общие настройки, отсутствие горизонтального переполнения. Выход кнопкой desktop удалил cookie; следующая навигация к API вернула `401`, тогда как отдельный мобильный сеанс продолжал получать `200`. Снимки прочитаны.

Отдельная настоящая проверка современного Manual enrollment: создание машины, отказ анонимному установщику, получение скрипта с enrollment credential, локальная регистрация и подключение. Терминал исполнителя выполнил установленный CLI `project list --json` с кодом 0 и корректным JSON без owner cookie на исполнителе. Тестовые терминал, машины и данные удалены, настройки QA восстановлены.

При дополнительных проверках подтверждены два неизменённых относительно исходного `main` пропуска: SQL первоначальной темы находился в server-модуле, а query-cost пример Workflows не задавал обязательный `workspace`. SQL вынесен в общий data helper; сервер по-прежнему выбирает тему и передаёт прежние значения. Пример использует shared workspace. Девять дополнительных задач typecheck/lint для DB/server и девять тестов авторизации, архитектуры и сохранности выбранной темы прошли.

Проверка стоимости запросов прошла через Turbo для `hosts-environments,credentials-attachments,settings-maintenance`: без недекларированного роста выше установленных порогов при увеличении истории и размера хода в 16 раз. Включены оба новых query helper. `hosts-environments` нужен для подготовки вложений зависимой группы; запуск одной группы credentials без этой подготовки не является корректным сценарием harness.

Конфигурация Compose проверена локально. Docker Engine на этом Mac не отвечал на API, поэтому локальная сборка контейнера не считается выполненной. Финальный код `e6c0df20bc5e3a137511a6d66dc1974cbeea8a0c` прошёл [Build AI Server на Ubuntu 22.04 x64](https://github.com/MAARRIIK/bb/actions/runs/45577509567): сборка архива, образ из тонкого контекста и настоящая проверка установленного пакета внутри контейнера. Linux-артефакт `AI-server-linux-x64` содержит архив, SHA256 и сведения о чистой сборке. Локальная повторная `smoke:server` после всех исправлений также прошла: 72 задачи. Общие upstream workflow на отдельных runner не объявляются прошедшими этой проверкой.

## Следующая проверка на VPS

Остаются настоящий DNS, получение и продление HTTPS-сертификата Caddy, доступ из внешней сети, физический iPhone Safari/PWA и восстановление резервной копии на целевом VPS. Совместимость официального TestFlight-клиента с новым входом не подтверждена. Работа выключенного компьютера не переносится автоматически на другой исполнитель; исходники и реквизиты провайдеров остаются на выбранной машине.
