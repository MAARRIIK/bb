## Единый диалог и сессии агентов

Нужно отделить постоянный диалог BB от сессий провайдеров. В текущем upstream диалог хранит один `providerId`, сервер валидирует модель внутри этого провайдера, а смена провайдера запускает handoff в новый диалог. Обычного плагина недостаточно для замены провайдера существующего диалога.

Для каждой сессии сохраняются провайдер, модель, идентификатор у агента и граница полученной истории. Ответы и инструменты остаются связанными со своей сессией; старые события не переписываются под нового провайдера.

Переключение выполняется после завершения или явной остановки активной работы под блокировкой диалога. После проверки подключения собирается пакет передачи, подготавливается новая сессия и фиксируется переход. Ошибка запуска не должна лишать пользователя возможности продолжить старой сессией. Набор инструментов, разрешений, контекстных показателей и текущего состояния интерфейса обновляется для целевого агента.

Первая версия может создавать свежую сессию на каждом переходе. Повторное использование сессий добавляется после проверки синхронизации: при возврате агент получает работу других моделей, которую ещё не видел. Новая сессия не означает новый видимый чат.

Полная лента и рабочий контекст модели различаются. В модель передаётся история в доступном окне либо сводка, последние сообщения, изменения и ссылки на файлы. Сохраняются резерв под ответ и инструменты, исходная граница событий и сведения о полноте передачи. Сводка не должна выдаваться за полную историю. Внутренние рассуждения и незавершённые вызовы инструментов между агентами не переносятся.

Зависимости между заданиями описаны ниже; параллельные рабочие ветки остаются отдельным этапом.

Зависимости [слиты в PR #19](https://github.com/MAARRIIK/bb/pull/19) и проверены настоящим циклом Codex → Qwen → Codex с перезапуском: [отчёт](./queue-task-dependencies-verification.md). Зависимое задание запускается только после подтверждённого успешного результата предшественника; UI, SDK и CLI используют один серверный допуск. Параллельные рабочие ветки остаются следующим отдельным этапом.

У задания есть запрос, вложения, проект, исполнитель/рабочая папка, модель и подключение, режим разрешений, состояние и зависимости. Контекст собирается перед запуском, чтобы следующая задача видела результат предыдущей.

В одном диалоге задачи выполняются последовательно. После ошибки зависимая задача ждёт решения пользователя. Ожидающие задания можно редактировать и переставлять без нарушения зависимостей. Переход к другой модели после лимита или ошибки возможен только по явно заданному правилу пользователя.

Параллельные независимые задачи запускаются в разных рабочих папках/ветках. Общая запись в одну рабочую папку сериализуется; слияние изменений — отдельный видимый шаг. Один браузерный чат обслуживает один активный запрос.

Очередь и её состояния сохраняются на сервере. Восстановление после перезапуска сверяет незавершённые операции, а не повторяет побочные действия вслепую. Повторная отправка с телефона не создаёт дубль задания.

## API и локальный исполнитель

Codex и Claude Code используют существующих провайдеров BB. Для Gemini, Kimi, GLM, DeepSeek и своего сервера добавляются адаптеры. API не предоставляет работу с диском сам по себе: общий исполнитель реализует чтение файлов, проверяемые патчи, команды и тесты с отображением действий в BB.

Каждое подключение объявляет фактические возможности: инструменты, изображения, файлы, лимиты контекста, авторизация и состояние сервиса. OpenAI-совместимость транспорта не означает одинаковую поддержку инструментов и параметров.

Для установленной `qwen2.5:7b` проверено окно 32 768 токенов, тогда как установленный Hermes требует минимум 64 000. Нужен совместимый путь исполнения, например адаптер Ollama с общим исполнителем. Увеличение заявленного числа в конфигурации без проверки реального окна не считается исправлением.

API-ключи хранятся защищённо, не включаются в историю, макет или Memory. Подписка веб-чата и доступ к API проверяются независимо.

## Остаток квот и расходы

Панель Provider usage расширена: остаток, источник, время измерения, точный сброс, область квоты и отметки устаревания проверены через настоящий сервис Codex и управляемый обрыв обновления: [отчёт](./usage-limit-details-verification.md). Доступность тех же данных через CLI и SDK сохранена. Показ рядом с моделью, дополнительные источники и допуск очереди по квотам остаются следующими пунктами.

Основа — существующий Provider usage и его контракт источников. Отображаются только реально доступные окна: часовые, пятичасовые, суточные, недельные и месячные. Остаток, область квоты, дата сброса, источник и время последнего обновления видны рядом с моделью и в общей панели.

Общие лимиты аккаунта или группы моделей не выдаются за независимые квоты каждой модели. Процент нельзя превращать в предполагаемое количество запросов. Баланс API, скорость запросов/токенов, пользовательский денежный бюджет и заполнение контекста — отдельные показатели.

Состояния неизвестных, устаревших и недоступных данных различаются. Ошибка обновления сохраняет прошлые измерения с отметкой устаревания. Отсутствие показаний не означает безлимитность. Перед запуском задания данные обновляются по возможности; подтверждённый лимит приостанавливает задачу до сброса или выбора другого подключения.

## Linux, macOS, iPhone и Android

Linux/macOS выполняют задачи, управляют файлами, CLI, локальными моделями и браузером. На iPhone работает адаптивный веб-интерфейс/PWA: запросы, очередь, чтение файлов и diff, подтверждения, статусы и результаты. Android использует тот же веб-интерфейс; мобильная оболочка и уведомления развиваются позднее.

Телефон не должен держать живым процесс агента. Отключение клиента не останавливает исполнение; после подключения он дочитывает события. Если исполнитель выключен, назначенные ему задачи ждут возвращения машины.

## VPS и подключённые машины

VPS у пользователя пока нет. До его появления готовятся воспроизводимая установка, резервное копирование и локальная проверка восстановления. Проверка на настоящем VPS остаётся открытой.

Сервер BB уже существует. Развёртывание включает Linux-VPS, постоянный каталог данных, управляемую службу, защищённый доступ через BB Connect или Tailscale Serve, резервное копирование и проверку восстановления. Для собственного домена нужны HTTPS, контроль доступа и корректная настройка внешнего URL/WebSocket.

Возможны два режима: всё выполняется на VPS; либо VPS хранит серверное состояние, а Mac/Linux подключены как исполнители. История и очередь остаются доступны при выключенном ноутбуке, но его задачи не выполняются автоматически на другой машине.

Проекты, worktree и локальное хранилище диалогов принадлежат своим исполнителям. Подключение машины не синхронизирует весь её диск. Смена рабочей машины требует явного переноса проекта или Git-процесса. Смена модели не должна незаметно менять рабочую папку.

Штатный перенос текущего сервера является экспериментальной функцией BB и выполняется отдельно с проверкой готовности, резервной копией и подтверждением пользователя. Сам этот план ничего не переносит.

## Язык и оформление

В настройках доступны русский, английский и автоматический язык. Ручной выбор хранится в общих настройках пользователя, применяется без перезапуска и работает на мобильных экранах. При автоматическом выборе учитывается устройство.

Локализуются встроенные меню, очередь, ошибки и уведомления. Даты и множественные числа используют выбранную локаль. Код, имена файлов, команды и вывод внешних программ не переводятся. Для плагинов нужен контракт локализации и резервный английский текст.

Язык ответов ИИ настраивается отдельно и по умолчанию следует интерфейсу. Оформление использует существующие токены темы BB, светлый/тёмный/системный режим и нейтральную палитру в стиле Codex.

## Экспериментальный DeepSeek Web

Браузерный адаптер на выбранном исполнителе отправляет задачу и нужные материалы в веб-чат, ждёт завершённого ответа, разбирает согласованный формат действий и возвращает результаты выполнения. Отдельная локальная нейросеть для исполнения не обязательна.

Вход выполняет пользователь в браузере исполнителя. CAPTCHA, повторный вход, лимит и изменение страницы приостанавливают задачу. Исполнитель проверяет операции, пути и права; он не выполняет произвольный текст ответа как shell-команду. Идентификаторы операций предотвращают повторное применение одного ответа.

Безлимитность не обещается. Пункт 3.5(3) условий DeepSeek ограничивает автоматизированное копирование контента; постоянный режим требует разрешённого способа использования. До этого модуль выключен по умолчанию; основная версия работает через API, локальные модели и штатных агентов. Возможен ручной перенос ответов.

## Этапы

1. Отдельная разработческая сборка, воспроизводимый запуск Linux/macOS, адаптивный интерфейс и локализация; подготовка развёртывания на VPS.
2. Сквозной прототип Codex → Claude → Codex в одном диалоге с передачей контекста и восстановлением после ошибок.
3. Очередь с выбором моделей, зависимостями и восстановлением; панель опубликованных квот.
4. API-адаптеры, общий исполнитель и совместимый путь Qwen/Ollama.
5. Независимый браузерный эксперимент при разрешённом доступе.
6. Повторное использование сессий, параллельные worktree, мобильные уведомления, Android и проверка выпуска.

Существующие события, очередь, провайдеры, Memory, разрешения и мобильные поверхности BB используются повторно. Новые действия доступны одинаково из UI, SDK и CLI. Изменения server/daemon-контрактов, миграции и публичные API следуют AGENTS.md upstream.

## Критерии приёмки

- Постоянный идентификатор диалога, сохранённая история и актуальный контекст после смены агента туда и обратно и перезапуска BB.
- Правильная привязка ответов, инструментов и подтверждений к сессиям; нет скрытой подмены модели или повторного выполнения команды.
- Несколько запросов разным моделям сохраняют порядок и зависимости; остановка и повтор работают предсказуемо.
- Закрытие iPhone не останавливает задания; восстановление соединения не теряет и не дублирует события.
- Недоступный исполнитель, ошибка входа и исчерпанная квота сохраняют задачу с понятной причиной ожидания.
- Общие квоты не дублируются, неизвестные значения не считаются безлимитными, часовой пояс и время сброса корректны.
- Права рабочей папки соблюдаются, передача контекста исключает секреты, облачный состав передачи виден пользователю.
- Русский и английский покрывают основные встроенные сценарии на компьютере и телефоне.
- Выполнены проверки запуска на Linux/macOS, Safari на iPhone, миграции и восстановления серверной базы.
