# Вход по подпискам: готовые провайдеры, плагины и skills

Исследование 24 ноября 2026 года после PR #30. Пользователь уточнил основной
сценарий: входить в аккаунты по подпискам; API-ключи сохранить как дополнительный
вариант. Новые транспорты и OAuth-клиенты пока не написаны и не установлены.
Рабочая IDE и её настройки не изменялись.

Вывод: для Google уже есть официальный ACP-путь. BB может использовать готового
агента, его инструменты и вход в аккаунт. Писать ещё один исполнитель Gemini
или собственный обмен Google-токенов не требуется. Для удобного входа из BB
нужно довести установку и представление авторизации, затем проверить реальный
аккаунт пользователя.

## Что изучено

Проверены manifest всех **50 локальных пакетов плагинов**, каталог **42 файлов
SKILL.md** в репозитории и подробные инструкции относящихся к задаче провайдеров,
ACP, аккаунтов, квот и проверки приложения. Это инвентаризация доступного кода,
а не утверждение, что все плагины включены или каждый сценарий проверен.

Сверен официальный ACP registry на коммите
[`cf3ba194`](https://github.com/agentclientprotocol/registry/tree/cf3ba194e35226b39fd9077c093e7c18d5487fc9):
46 агентов. Реальные manifest переданы существующему парсеру BB: 46 приняты,
0 пропущены. Проверены генерация настройки Gemini и принятие custom-конфигурации
Antigravity. Ничего не записывалось в пользовательские настройки.
Прямой CDN registry вернул HTTP 403 из исследовательского окружения; GitHub
репозиторий прочитан успешно. Доступность CDN внутри самой IDE этим не доказана.

Среди внешних решений просмотрены OpenCode, `opencode-antigravity-auth`, Pi,
официальные коллекции Anthropic/Vercel и Superpowers; для skills дополнительно
прочитаны реальные файлы frontend-design, React best practices, find-skills,
systematic-debugging и using-git-worktrees. Ориентир распространённости —
[каталог skills.sh](https://skills.sh/), не обещание исчерпывающего обзора всех
пакетов интернета. Сторонние инструкции прочитаны как данные, не установлены.

## Вход в модели без API-ключа

| Решение | Что уже готово | Что делать в BB |
| --- | --- | --- |
| Google Antigravity | Официальный Google OAuth, повторное использование локального входа, ACP | Использовать существующий `provider-acp`; основной кандидат для подписки Google |
| Gemini CLI | Официальный Google sign-in и запись `gemini` в ACP registry | Существующее `bb acp add gemini`; затем вход на машине и проверка аккаунта |
| Codex | Отдельный штатный BB-плагин и вход Codex | Сохранить уже используемый путь, не заменять Pi-обёрткой |
| Claude Code | Отдельный штатный BB-плагин и авторизация CLI | Проверять штатный путь Claude отдельно от Pi и от API |
| GitHub Copilot CLI | Запись `github-copilot-cli` в официальном ACP registry | Подключать существующим ACP-путём при наличии доступа Copilot |
| Kimi Code | Официальный `kimi-code` в ACP registry | Проверить штатный login и условия аккаунта; не путать с ключом Moonshot API |
| Pi | Подписочные входы для ряда провайдеров, API и локальные модели | Оставить для поддерживаемых входов и Qwen/Ollama; Gemini в установленной версии настроен через API |
| OpenCode | ACP-путь в BB, подключения и собственная система плагинов | Переиспользовать, если нужного входа нет в более прямом штатном агенте |

Google прямо описывает команду `agy acp`, передачу JSON-RPC по stdin/stdout и
повторное использование настроек и входа агента внутри стороннего редактора.
Для входа предлагается интерактивный `agy` либо `agy acp --login`:
[официальный ACP guide](https://antigravity.google/docs/cli/acp/),
[авторизация Antigravity](https://antigravity.google/docs/install/).
Тариф Google и доступные квоты нужно подтвердить после входа; срок подписки
12 месяцев сам по себе не определяет её уровень.

У Gemini CLI официальный вход Google также учитывает связанный Pro/Ultra
аккаунт: [authentication](https://geminicli.com/docs/get-started/authentication/).
В исследованном registry версия `0.71.1`, запуск через
`npx -y @google/gemini-cli@0.71.1 --acp`. Это снимок каталога, а не обязательная
версия для будущей установки; обновление следует делать штатным механизмом BB.

Подписочный вход не универсален для всех моделей. Например, registry содержит
сторонний GLM Agent, но одна запись в каталоге не доказывает вход без ключа.
API-баланс, подписка веб-чата и доступ к CLI должны проверяться раздельно.
Установленная документация Pi также отдельно указывает, что Claude через
сторонний harness может расходовать платную extra usage; нельзя автоматически
обещать расходование включённых лимитов подписки через любую обёртку.

## Точный зазор Antigravity в текущем BB

В registry уже есть `antigravity-acp` от Google LLC, версия `1.5.2`, в том числе
официальный binary для macOS ARM64 с SHA-256. У BB уже есть его registry icon.
Но `plugins/provider-acp/src/registry.ts` автоматически добавляет только npx/uvx;
бинарные агенты сейчас получают `manual-install`. Команда `bb acp add
antigravity-acp` в этой реализации не скачает бинарник.

Отдельный официальный CLI можно зарегистрировать существующей настройкой
`customAgents`, без нового провайдера. Конкретная запись проходит нынешнюю схему:

```json
{
  "id": "antigravity",
  "displayName": "Google Antigravity",
  "command": "agy",
  "args": ["acp"]
}
```

Это пример одной записи, а не команда перезаписи всего `customAgents`:
существующие подключения нужно сохранить. На проверенной машине `agy` не найден;
реальный запуск, Google OAuth и задача с подпиской ещё не выполнены.
Нужно выбрать один поддерживаемый способ установки — официальный CLI или
официальный registry binary — и проверить его фактическую совместимость.

Общий ACP bridge уже умеет обнаруживать методы авторизации и строить инструкции
входа. Custom agent пока не получает собственной удобной кнопки guided sign-in;
эта часть требует проверки UI, а не дублирования хранения Google-токенов.

## Сторонний Antigravity OAuth-плагин

[`NoeFabris/opencode-antigravity-auth`](https://github.com/NoeFabris/opencode-antigravity-auth)
— готовое решение для OpenCode с Google OAuth, каталогом моделей, аккаунтами и
показом квот. Это, вероятно, один из вариантов, который пользователь имел в виду.
Исследованный README описывает OpenCode 2.1.2+, плагин 2.1.2 и вход
`opencode auth login google`; старые инструкции для OpenCode 1.x отличаются.

Автор прямо называет интеграцию неофициальной и предупреждает о возможных
ограничениях Google для сторонних клиентов. Поэтому при наличии официального
Antigravity ACP он не выбран основным путём. Он полезен как кандидат и источник
сравнения, но его токены и частные endpoint не нужно копировать в BB.
[Плагины OpenCode](https://opencode.ai/docs/plugins/) и
[подключения OpenCode](https://opencode.ai/docs/providers/) — отдельный слой,
запускаемый через уже имеющийся ACP-провайдер BB.

## Какие skills полезны

| Набор | Польза для форка | Решение |
| --- | --- | --- |
| Локальные acp-provider / codex-provider / claude-code-provider / pi-provider | Знают реальные команды и ограничения BB | Использовать первыми |
| Локальные verify-bb / test-audit / deslop | Реальная QA и требования репозитория | Уже применяются; не дублировать общей методологией |
| [Vercel skills / find-skills](https://github.com/vercel-labs/skills) | Поиск готовых skills, версии и lock-файл | Использовать как каталог перед созданием нового skill |
| [Vercel agent-skills](https://github.com/vercel-labs/agent-skills) | React performance, web design review | Брать подходящие React-рекомендации; BB не является Next.js, RSC-правила не применять вслепую |
| [Anthropic skills](https://github.com/anthropics/skills) | Frontend design, документы, PDF, spreadsheets | Дизайн сверять с выбранным оформлением Codex и токенами BB; документные возможности уже есть среди доступных skills |
| [Superpowers](https://github.com/obra/superpowers) | Диагностика, планирование, worktree и завершение веток | Отдельные приёмы полезны; полный пакет не включать поверх правил BB и запрета пользователя на дополнительных агентов |
| Playwright / dev-browser и локальная browser automation | Проверка UI и браузерных сценариев | Переиспользовать имеющиеся инструменты; не писать ещё один браузерный исполнитель |

Skill — инструкции и вспомогательные ресурсы. Он не выдаёт подписку, не добавляет
OAuth на стороне сервиса и не заменяет работающего провайдера.

## Следующий конкретный этап

1. Использовать существующий ACP для официального Antigravity и сохранить
   Gemini CLI как второй штатный вариант; API-панель Pi оставить.
2. Подготовить установку и понятный вход из IDE через общий механизм провайдеров,
   не копируя Google-токены и не переписывая executor.
3. В собственной QA проверить запуск без аккаунта, понятное состояние входа,
   CLI/SDK/UI, ошибку и восстановление. Затем пользователь выполняет Google login
   в браузере; пароль и токены в чат не нужны.
4. Подтвердить настоящую задачу, доступные модели, источник квот и работу после
   перезапуска. До этого не отмечать Google-подписку проверенной.

Доказательства исследования сохранены локально в `.tmp/subscription-integrations/`:
manifest локальных плагинов, снимок registry и `bb-existing-registry-proof.json`.
Исследование не меняло запущенную IDE, не добавляло аккаунты и не запускало
сторонние установщики или skills.
