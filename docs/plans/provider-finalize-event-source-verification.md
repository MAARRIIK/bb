# Источник события после завершения смены провайдера

Дата: 24 ноября 2026. Основа: PR #17, `646e0b27188e827601ea249f17aaa38fdd1bc994`. Проверенные исходники: `6f19ecb`; отчёт добавлен после живой проверки.

## Причина и исправление

В живой проверке PR #17 переход и запрос модели завершились, но daemon потерял служебное `thread/identity`: сервер вернул `400 Bad Request - Unrecognized key: "providerThreadId"`.

При `finalizeProviderSession` runtime передавал полную целевую сессию в аргумент `ProviderSessionSource`. TypeScript допускает такой объект по структурному типу. В памяти оставалось дополнительное `providerThreadId`, хотя строгий wire-контракт источника разрешает только `providerId` и `providerSessionId`. Идентификатор native-сессии уже находится в самом событии. Daemon передавал лишнее поле серверу, где весь такой event group отклонялся.

Исправлен один вызов: источник собирается явно из двух разрешённых полей. Полезная нагрузка события и его native ID сохраняются. Новых API, миграций и изменения установленного wire-контракта нет; протокол **283** остаётся совместимым. Строгая валидация сервера сохранена.

## Воспроизведение и проверки

Он сохраняет реальные события вместе с источниками, выделяет новую сессию по провайдеру и поколению и применяет тот же строгий `providerSessionSourceSchema`, который входит в daemon-контракт.

До исправления проверка упала с точным `Unrecognized key: "providerThreadId"`. Первый вариант проверки также обнаружил совпадение native ID разных тестовых провайдеров; фильтр исправлен с учётом провайдера и поколения до подтверждения требуемого сбоя.
