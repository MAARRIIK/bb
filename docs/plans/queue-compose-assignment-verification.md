# Выбор модели до добавления запроса в очередь

Дата: 24 ноября 2026. Основа: PR #16, `3c70f718c9f8a0b872737d1ddbe1c183f8399ac2`. Проверенные исходники: `46c4ba8`; отчёт добавлен после живой проверки.

## Результат

Над полем ввода готового диалога появилась кнопка «В очередь с моделью». Она открывает общую форму назначения провайдера, модели, разрешений, обдумывания, режима обслуживания и правила передачи контекста. Кнопка недоступна для пустого черновика, во время загрузки вложений или отправки. При архивном, удалённом workspace, handoff и активном запросе подтверждения действие не показывается вместе с основным редактором.

«Добавить в очередь» отправляет текущие текст и вложения с полным назначением одним вызовом существующего SDK `threads.queuedMessages.create`. Предварительного создания задания с моделью текущего диалога нет. Соответствующий CLI уже существует: `bb thread queue create --provider ... --model ... --permission-mode ... --provider-switch-policy manual|recent-messages`. Руководство CLI и Plugin Guide дополнены.

Обычная отправка и её горячие клавиши сохраняют свой путь. Назначение само по себе не переключает активного агента. По умолчанию правило `manual`; флажок автоперехода требует явного выбора и сбрасывается при смене провайдера. Задание может запуститься сразу в свободном диалоге либо дождаться завершения текущего хода и других условий очереди.

Отмена не изменяет черновик. На время отправки форма блокируется; общий `useDraftSubmission` удерживает отправку этого черновика между экземплярами редактора и после повторного монтирования. `sendPromptDraft` восстанавливает отклонённые текст и вложения рядом с более новыми правками. Ошибка отображается в открытой форме; можно повторить с выбранной моделью. Успешное создание обновляет очередь и уведомляет редактор о принятии запроса. Новый черновик можно писать во время работы модели.

Редактирование уже созданных заданий использует ту же форму. Для каждого открытия создаётся новый экземпляр её локального состояния, а мобильный drawer сохраняет свою оболочку. Новых полей API, миграций и host-daemon wire нет; версия протокола остаётся **283**.

## Найденное ограничение и следующие шаги

При завершении перехода daemon отправил служебное `thread/identity`, которое сервер отклонил: `400 Bad Request - Unrecognized key: "providerThreadId"`. Подготовленный переход и пользовательский запрос завершились, файл и ответ получены, но потерю служебного события нельзя считать нормой. Этот код не менялся данным этапом. Предварительное чтение указывает на передачу полной сессии в поле `source`, контракт которого допускает только провайдера и поколение; воспроизведение и исправление выделены следующим этапом.

Зависимости заданий, параллельные ветки, оставшаяся локализация, API-провайдеры и квоты остаются в roadmap. Здесь проверена перезагрузка браузера; новый перезапуск server/daemon не заявляется. Safari/iPhone не проверен из-за отсутствующего iOS Simulator; Chromium 390 его не заменяет. Linux, Android и VPS этим этапом не проверялись.
