# Основа локализации: первый результат

Ветка: `personal/language-foundation`. Основание: план `31a7b6c564864712d6fcbfc8d0d091d54b236a7c` поверх upstream `796cdcc0f4bf8a55e23664035c54e8db6fe9d272`.

## Реализовано

- Выбор языка интерфейса: `system`, `en`, `ru`, по умолчанию `system`.
- Общая настройка сервера, живое обновление подключённых клиентов и приоритет ручного выбора над языком устройства.
- Отдельный каталог русских строк с английским резервным текстом. Первая партия переводит навигацию настроек и часть основных настроек и оформления. Полная локализация ещё не завершена.
- Постоянные английские якоря настроек и поиск переведённых пунктов. Код и внешний вывод не проходят через переводчик.
- UI в General, существующая команда `bb settings general interfaceLanguage ru` и существующий SDK `system.updateGeneralSettings` используют одну серверную настройку. Старые клиенты, не отправляющие новое поле, сохраняют выбранный язык.

## Проверка

Среда: macOS arm64, Node 22.19.0, pnpm 9.15.0, зависимости из неизменённого lockfile. Запуск через `pnpm dev` в отдельной пустой базе с маркером владения; рабочая база установленного BB не использовалась.

Проверка инвентаря verify-bb обнаружила исходное расхождение: семейство CLI `diagnostics` не имеет владельца рецепта. Полная сверка карты требует отдельного исправления; baseline автоматически не перезаписывался. Для новой настройки добавлен целевой рецепт в `features/settings.md`.
