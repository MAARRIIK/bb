# Подготовка и принятие сессии провайдера

Основание: `ad45d2b9190df428328232788000bd4945be6a89`, слитый [PR #8](https://github.com/MAARRIIK/bb/pull/8). Это внутренний механизм исполнителя для следующего этапа переключения. Пользовательская смена провайдера ещё не включена.

## Поведение

`thread.session.prepare` создаёт свежую нативную сессию в отдельном процессе поколения. Команда не принимает пользовательский ввод или fork, не заменяет текущего владельца и сохраняет настоящий `BB_THREAD_ID` и каталог диалога в окружении агента. Повтор с тем же lease и аргументами возвращает тот же результат; повторное использование lease с другими аргументами отклоняется.

`thread.session.adopt` повторно проверяет источник, нативный ID и отсутствие незавершённых операций, хода, фоновой работы, инструментов и подтверждений. Прежняя сессия сохраняется для отката. После принятия новые запросы и обычные управления заблокированы до завершения перехода.

`thread.session.finalize` освобождает старую сессию, публикует идентичность новой и сохранённые начальные сведения. Команды, события, инструменты и recovery-подсказки учитывают внутренний ID моста, сохраняя постоянный ID видимого диалога. Поздние события освобождённого владельца не используют fallback на единственный соседний диалог того же процесса.

`thread.session.rollback` возвращает сохранённого владельца и освобождает подготовленную сессию. Если процесс новой сессии уже завершился, откат остаётся возможен. Если завершился и прежний процесс, результат `session: null` честно сообщает, что живой сессии нет; её дальнейшее восстановление принадлежит серверному контроллеру. `thread.session.discard` освобождает подготовку; после принятия требуется явный откат или завершение. Ошибка очистки сохраняет lease для повторной попытки.

Все пять команд проходят через существующую последовательную очередь диалога. Подготовка и принятый переход удерживают рабочую среду от выгрузки и защищают обе стороны от idle reaper. Сведения подготовки не попадают в историю и heartbeat как отдельные диалоги. Для смены среды нужна отдельная операция: подготовка не забирает владельца из другой среды.

`HOST_DAEMON_PROTOCOL_VERSION` повышен до **281**. Новые команды не повторяются транспортом автоматически после потери исполнителя. Пользовательские UI/SDK/CLI действия и Plugin SDK в этом этапе не добавляются; будущий общий серверный путь должен использовать эти команды.

## Проверка

macOS arm64, изолированный Node 22.19.0 и pnpm 9.15.0. Проверки используют реальные тестовые процессы моста и настоящую мигрированную SQLite. Рабочая база и диалоги BB не использовались.

Полный последовательный граф Turbo прошёл:

| Набор       | Пройдено | Пропущено |
| ----------- | -------- | --------- |
| Сервер      | 4443     | 3         |
| Исполнитель | 908      | 14        |
| Runtime     | 327      | 1         |
| Протокол    | 97       | 0         |

Всего **5775** пройденных проверок, 18 пропусков. После дополнительных исправлений обработки уведомлений повторно прошли полные runtime и исполнитель: 327 и 908 проверок соответственно. Источники и тесты не менялись во время Vitest.

Новые сценарии проверяют прямой переход с инструментом в новом поколении, сохранение соседнего диалога общего процесса, одинаковые повторы, ошибку подготовки, discard, rollback, завершение процесса новой сессии до/после принятия, активный ход и фоновую работу прежнего агента, idle reaper, обновление окружения и порядок команд через настоящий CommandRouter.

Отрицательные проверки воспроизвели четыре ошибки до исправлений или при временном отключении защиты:

- обновление окружения выгружало старую и подготовленную сессии;
- запрос, следующий за finalize, пересекался с ещё не завершённой очисткой;
- первоначальное extension-состояние нового агента терялось;
- событие освобождённой нативной сессии попадало соседнему диалогу через fallback.

Временные мутации восстановлены. Типы, lint, type-aware lint и сборки сервера/исполнителя прошли одним графом: 17 задач Turbo. Дополнительно прошли 2 проверки, типы и type-aware lint самого тестового провайдера (8 задач Turbo). `git diff --check` прошёл; дифф просмотрен по `docs/CODE_REVIEW.md` и deslop.

Интеграционный запуск с `-t '^$'` успешно выполнил сборку мостов и обнаружение сценариев; все 56 live-проверок намеренно пропущены. Это не проверка реальных ответов Codex, Claude или Pi.

```sh
pnpm exec turbo run test --concurrency=1 --env-mode=loose --filter=@bb/server --filter=@bb/host-daemon --filter=@bb/agent-runtime --filter=@bb/host-daemon-contract
pnpm exec turbo run test --concurrency=1 --env-mode=loose --filter=@bb/agent-runtime --filter=@bb/host-daemon
pnpm exec turbo run typecheck lint lint:type-aware build --filter=@bb/agent-runtime --filter=@bb/host-daemon --filter=@bb/host-daemon-contract --filter=@bb/server
pnpm exec turbo run test:integration --concurrency=1 --env-mode=loose --filter=@bb/agent-runtime -- -t '^$'
```

Из окружения тестов удалены адреса и идентификаторы рабочего BB; используется отдельный npm-кэш. Журналы находятся в `.tmp/toolchain/test-prepared-*` и `.tmp/toolchain/check-prepared-*`. Раздельные графы с общими генерируемыми артефактами не запускались параллельно.

## Следующий этап

Нужны сохранённое сервером намерение перехода, сверка после перезапуска, атомарное обновление текущего поколения, фильтрация актуальных сведений по нему и пакет истории в фактическом окне модели. Затем — один путь UI/SDK/CLI и сквозная проверка переключения туда и обратно. Подготовка пустой нативной сессии не считается проверкой авторизации или готовности модели отвечать. Linux, Safari/iPhone и VPS этим этапом не подтверждены; VPS пока отсутствует.
