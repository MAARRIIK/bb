# Зависимости заданий очереди

Дата: 24 ноября 2026. Основа: PR #18, `54d3b2bd3fd781f7ba7bcd54f8c9eb8e18da613c`. Проверенные исходники: `c0035f8b03a21a4a5f4706f7f39e88a5861477bd`; после проверки добавлены только отчёт и ссылки в документации.

## Результат

Задание может ждать успешного завершения до 16 явно выбранных обычных заданий того же диалога. Общая форма назначения при создании и редактировании показывает зависимости, очередь — их количество и причину ожидания. SDK `threads.queuedMessages.create/update` принимает `dependsOnQueuedMessageIds`; CLI поддерживает повторяемый `--depends-on` и `--clear-dependencies`. Руководство CLI, Plugin Guide и описание проверяемого API обновлены.

Результат хранится отдельно от строки очереди: изъятие запроса для отправки ещё не означает успешное выполнение. Успех фиксируется только по принятому запросу и завершению его корневого хода с совпадающими провайдером и поколением. Позднее событие старой сессии не освобождает зависимое задание. Отказ, подтверждённая остановка и удаление сохраняют failed/cancelled; повтор исходного запроса обновляет его запись запуска. Независимая задача может пройти мимо удержанной.

Зависимости проверяются до подготовки провайдера и повторно при допуске. «Отправить сейчас», steer и перестановка не обходят их. Самоссылки, циклы, чужие и отсутствующие задания отклоняются. Группировка требует одинаковых зависимостей. Будущее время отправки и удержания плагинов сохраняются при освобождении зависимости; истёкший таймер не создаёт повторяющийся цикл пробуждения.

Миграция `0171_unusual_naoko` добавляет поле списка зависимостей и таблицу `queued_task_runs`. Она и snapshot сгенерированы Drizzle. Индексы обслуживают запросы по ID, запросу, ходу и состоянию диалога. Изменение результата и фиксация события выполняются в одной транзакции. Изъятие claim и привязка нового requestId также атомарны. Новых host-daemon wire-полей нет; протокол остаётся **283**.

## Настоящее приложение

Отдельный checkout проверенных исходников, новая помеченная база, собственные порты, браузерный профиль, временный Git-проект и конфигурация Pi. Проверка не использует базу рабочей IDE. Производный псевдоним `qwen2.5:7b` обслуживается Ollama с фактическим окном **32768**, подтверждённым `/api/ps`.

1. Настоящий Codex запомнил контрольную фразу `BB_DEPENDENCY_CONTEXT_20261124` без работы с файлами.
2. Родительское задание назначено Pi/Qwen через CLI. Зависимое задание создано одним действием настоящей мобильной формы: Codex, явное согласие на переход с последними сообщениями, зависимость от родителя. Перестановка поместила потомка перед родителем.
3. «Отправить сейчас» вернул `409 queued_message_still_waiting`; steer сохранил `delivery: queued`. Ни один путь не вызвал провайдера: оставался один начальный запрос, ноль отказов и ноль переходов. Результирующих файлов ещё не было.
4. Родитель запущен по расписанию. Выполнен автоматический переход Codex → Pi. Qwen получил контрольную фразу из предыдущей истории и настоящим инструментом создал `dependency-parent.txt`, затем ответил `РОДИТЕЛЬ_ГОТОВ`. Сохранён succeeded, подтверждение и завершение связаны с одним requestId, провайдером, поколением и ходом.
5. Потомок оставался отложенным. Полностью остановлены и вновь запущены процессы изолированной сборки. Родительский succeeded, зависимость и будущее время потомка сохранились; второго файла не было. Число запросов оставалось два. Черновик `Черновик после зависимой очереди` сохранился после восстановления страницы.
6. Время потомка изменено через CLI на ближайший запуск. Выполнен автоматический переход Pi → Codex в том же диалоге и рабочей папке. ## Ограничения

Форма предлагает обычные задания, ещё находящиеся в очереди, и сохраняет выбранные ID после их допуска. Отдельного обозревателя всей истории завершённых заданий и настройки срока хранения результатов пока нет. Сохранность выбранного ID проверена DB/SDK и перезапуском; повторное открытие UI после исчезновения родителя отдельно не проверялось.

Safari/iPhone не проверен: iOS Simulator отсутствует. Chromium на macOS его не заменяет. Linux, Android, настоящий VPS, другие облачные провайдеры, параллельные рабочие ветки и панель квот остаются отдельными пунктами roadmap.
